## Schema 在 Vault 中的作用分析

经过对源码的全面分析，以下是 Schema 系统的完整解读：

### 一、Schema 是什么？

Schema 本质上是一个**笔记层级结构的蓝图/模板定义系统**。它告诉引擎：*"当用户在某个层级下创建笔记时，应该遵循什么样的结构，并且可以自动应用什么模板"*。

Schema 以 `.schema.yml` 文件的形式存储在 vault 中，每个 vault 至少有一个 `root.schema.yml`。

### 二、Schema 的文件格式

**类型定义** (`packages/common-all/src/types/typesv2.ts:156-191`)：

```yaml
# 一个 .schema.yml 文件的结构
version: 1              # 版本号，目前固定为 1
imports: []             # 可以导入其他 schema 文件
schemas:                # schema 定义列表
  - id: daily           # Schema 的唯一标识（也用作路径匹配 pattern）
    parent: root        # 父 schema
    title: Daily Notes
    desc: "每日笔记"
    children:
      - pattern: journal    # 匹配 daily.journal
        children:
          - pattern: "*"    # namespace 模式，匹配 daily.journal.* (如 daily.journal.2024-01-01)
            namespace: true
            template:       # 为匹配的笔记自动应用模板
              id: templates.daily-journal  # 模板笔记的 fname
              type: note
```

**Schema 数据属性** (`packages/common-all/src/types/foundation.ts:216-227`)：

```typescript
type SchemaData = {
  namespace?: boolean;       // 是否为命名空间（匹配任意子节点）
  pattern?: string;          // 匹配模式（支持 glob），默认使用 id
  template?: SchemaTemplate; // 关联的模板
  isIdAutoGenerated?: boolean;
  desc?: string;
};

type SchemaTemplate = {
  id: string;               // 模板笔记的 fname
  type: "snippet" | "note"; // 模板类型
};
```

### 三、Schema 的三大核心作用

#### 1. 🗂️ **层级路径匹配（Path Matching）**

Schema 的核心功能是将**笔记路径**与**预定义的层级结构**进行匹配。

**实现位置**: `SchemaUtils.matchPath()` — `packages/common-all/src/dnode.ts:1555-1581`

```typescript
// 匹配流程：
// 1. 从笔记的 fname 中提取 domain（第一段路径）
// 2. 查找同名的 schema module（如 "daily" 笔记查找 daily.schema.yml）
// 3. 从 root schema 开始，逐层递归匹配

static async matchPath(opts: {
  notePath: string;
  engine: DEngineClient;
}): Promise<SchemaMatchResult | undefined> {
  const domainName = DNodeUtils.domainName(notePath); // "daily.journal.2024" → "daily"
  const resp = await opts.engine.getSchema(domainName);
  if (!resp.data) return; // 没有对应 schema 就跳过
  
  // 逐层匹配
  return SchemaUtils.matchPathWithSchema({
    notePath,
    matched: "",
    schemaCandidates: [domainSchema],
    schemaModule: resp.data,
  });
}
```

**匹配使用 `minimatch` glob 模式**（`dnode.ts:1673-1710`）：

```typescript
// 笔记路径中的 "." 被替换为 "/"，然后做 glob 匹配
const notePathClean = notePath.replace(/\./g, "/");
// 如 "daily/journal/2024-01-01" 匹配 "daily/journal/*"
return minimatch(notePathClean, pattern);
```

#### 2. 📝 **自动模板应用（Template Application）**

当笔记匹配到一个带 `template` 属性的 schema 时，会自动将模板内容应用到新笔记上。

**实现位置**: `TemplateUtils.findAndApplyTemplate()` — `packages/common-server/src/template.ts:198-251`

```typescript
static async findAndApplyTemplate({ note, engine, pickNote }) {
  // 1. 从笔记的 schema 属性找到对应的 SchemaModule
  const maybeSchema = await SchemaUtils.getSchemaFromNote({ note, engine });
  
  // 2. 获取 schema 中定义的 template
  const maybeTemplate = maybeSchema?.schemas[note.schema?.schemaId].data.template;
  
  // 3. 根据 template.id 查找模板笔记
  const maybeNotes = await engine.findNotes({ fname, vault: maybeVault });
  
  // 4. 使用 Handlebars 模板引擎渲染并应用
  TemplateUtils.applyTemplate({ templateNote, targetNote: note, engine });
}
```

模板支持 **Handlebars** 变量，如 `{{CURRENT_YEAR}}`、`{{TITLE}}`、`{{FNAME}}` 等（见 `template.ts:63-98`）。

#### 3. 🔍 **Lookup 自动补全（Schema Completions）**

在 Note Lookup（笔记查找/创建）时，schema 提供**基于层级结构的智能补全建议**。

**实现位置**: `NoteLookupProvider` — `packages/vscode_plugin/src/components/lookup/NoteLookupProvider.ts:359-418`

```typescript
// 用户输入 "daily.journal." 时
// 1. 用 "daily.journal" 匹配 schema
const results = await SchemaUtils.matchPath({
  notePath: queryUpToLastDot, // "daily.journal"
  engine,
});

// 2. 获取 schema 的 children，生成补全候选
const candidates = schema.children.map((ent) => {
  const mschema = schemaModule.schemas[ent];
  if (SchemaUtils.hasSimplePattern(mschema)) {
    const pattern = SchemaUtils.getPattern(mschema);
    const fname = [dirName, pattern].join(".");
    // 创建 schemaStub 笔记作为补全候选项
    return NoteUtils.fromSchema({ schemaModule, schemaId: ent, fname, vault });
  }
});
```

这些候选项在 lookup 面板中显示为 **schemaStub**（带 `$(gist-new)` 图标），用户选择后即可快速创建符合 schema 结构的笔记。

### 五、实际使用示例

假设你有以下 `daily.schema.yml`：

```yaml
version: 1
imports: []
schemas:
  - id: daily
    parent: root
    title: Daily
    children:
      - pattern: journal
        children:
          - pattern: "[0-9][0-9][0-9][0-9]"
            children:
              - pattern: "[0-9][0-9]"
                children:
                  - pattern: "[0-9][0-9]"
                    template:
                      id: templates.daily-journal
                      type: note
```

那么当你创建 `daily.journal.2024.01.15` 这个笔记时：
1. **路径匹配**: `daily` → `journal` → `2024` → `01` → `15` 每一层都匹配成功
2. **模板自动应用**: 最末层关联了 `templates.daily-journal`，所以新笔记自动填充该模板的内容
3. **lookup 补全**: 输入 `daily.journal.2024.01.` 时，会自动建议符合 `[0-9][0-9]` 模式的候选项

### 总结

**Schema = 笔记层级的"类型系统"**。它定义了 vault 中笔记的结构规范，提供三大能力：
1. **结构约束** — 定义允许的层级结构和命名模式
2. **模板注入** — 自动为匹配的新笔记应用预设模板
3. **智能补全** — 在 lookup 时提供基于 schema 的路径建议
